Kapcsolásszervezési módok

ÁramkörkapcsolásDedikált útvonal foglalódik le a teljes kommunikáció idejére. Pl.: telefonhálózat. Garantált sávszélesség, de pazarló.
CsomagkapcsolásAz adat kis csomagokra bontva, önállóan halad. Pl.: Internet. Hatékonyabb, de késleltetés és veszteség lehetséges.

Csomagvesztés és késleltetés

  • Feldolgozási késleltetés – a csomag fejlécének vizsgálata az útválasztóban
  • Várakozási késleltetés – sor (queue) a kimeneti linken
  • Átviteli késleltetés – csomag mérete / link sávszélesség
  • Terjedési késleltetés – fizikai távolság / fény sebessége

HTTP Fontos

  • Kliens-szerver modell, kérés-válasz alapú
  • HTTP/1.0: minden kéréshez új TCP kapcsolat (nem perzisztens)
  • HTTP/1.1: perzisztens kapcsolat, pipelining
  • Metódusok: GET, POST, PUT, DELETE, HEAD
  • Állapotkódok: 200 OK, 301 Moved, 404 Not Found, 500 Server Error
  • Állapotmentes (stateless) – cookie-k kompenzálják

FTP

  • Két kapcsolat: vezérlő (21-es port) és adat (20-as port)
  • Állapotteljes – tartja nyilván az aktuális könyvtárat, felhasználót

DNS Fontos

  • Doménnév → IP cím feloldás
  • Hierarchikus, elosztott adatbázis
  • Rekord típusok: A (IPv4), AAAA (IPv6), MX (mail), CNAME (alias), NS (névszerver)
  • Iteratív és rekurzív lekérdezés
  • Gyorsítótárazás (caching) TTL értékkel

Socketek

  • Alkalmazás és a hálózat közötti interfész (API)
  • Azonosítás: IP cím + port szám
  • UDP socket: cím + port elég; TCP socket: forrás+cél IP+port (4-es)

TCP részletesen Fontos

  • Háromfázisú kézfogás (3-way handshake): SYN → SYN-ACK → ACK
  • Nyugtázás (ACK): kumulatív, a következő várt bájt sorszámát jelzi
  • Forgalomszabályzás (flow control): fogadó ablak (rwnd) – a fogadó puffer szabad helyét jelzi
  • Torlódáskezelés (congestion control): lassú indítás → torlódás elkerülés → gyors visszaállítás
  • Kapcsolat bontás: 4 lépéses FIN-ACK csere

Portok besorolása

  • Jól ismert portok: 0–1023 (HTTP: 80, HTTPS: 443, FTP: 21, SSH: 22, DNS: 53)
  • Regisztrált portok: 1024–49151
  • Dinamikus/privát portok: 49152–65535

Nyalábolás és nyalábbontás (Multiplexing/Demultiplexing)

Nyalábolás: több alkalmazás adatát egyetlen hálózati kapcsolaton küldjük. Nyalábbontás: a fogadó oldalon portszám alapján szétválasztjuk a csomagokat a megfelelő alkalmazásokhoz.

Hálózati réteg (IP, routing) ▼

IPv4 Fontos

  • 32 bites cím, ponttal elválasztott 4 oktet (pl. 192.168.1.1)
  • Fejléc mezők: TTL, protokoll, forrás/cél IP, fragmentálás mezők
  • Fragmentálás: ha a csomag nagyobb mint az MTU, feldarabolódik; cél újrarakja össze

Alhálózatok és maszkok Fontos

  • Alhálózati maszk jelöli a hálózat részt: /24 = 255.255.255.0
  • CIDR (osztályfüggetlen): pl. 192.168.1.0/26 = 64 cím, 62 gép
  • Hálózati cím: első cím; Broadcast: utolsó cím
  • Hasznos képlet: 2^(32-prefix) = összes cím, −2 = gépek száma
VLSM (változó hosszúságú maszk) feladatoknál mindig a legnagyobb alhálózattal kezdj!

IPv6

  • 128 bites cím, kettősponttal elválasztott 8 × 16 bit hexadecimálisan
  • Nincs fragmentálás útválasztóban, nincs checksum, nincs broadcast
  • Fejléc egyszerűbb, kiterjesztett fejlécek opciósan

DHCP, NAT, ICMP

  • DHCP: automatikus IP kiosztás (Discover → Offer → Request → ACK)
  • NAT: privát IP-ket egyetlen publikus IP-re fordít; portszámmal különbözteti meg a kapcsolatokat
  • ICMP: hibakezelés és diagnosztika (ping = echo request/reply, traceroute)

Adatkapcsolati réteg ▼

Szolgáltatások és ARP

  • Keretezés, hibakezelés (CRC), hozzáférés-vezérlés (MAC)
  • MAC cím: 48 bit, hardverbe égetett, pl. AA:BB:CC:DD:EE:FF
  • ARP: IP cím → MAC cím fordítás; broadcast kérdés, unicast válasz; ARP tábla gyorsítótárazza

LAN, STP, VLAN Fontos

  • Switch (kapcsoló): MAC tábla alapján továbbít; hurok veszély → STP!
  • STP (Spanning Tree Protocol): hurokmentessé teszi a hálózatot; root bridge választás, portok állapota: root, designated, blocked
  • VLAN: logikai szétválasztás egy fizikai hálózaton belül; 802.1Q tag jelöli a keretek VLANját; trunk port viszi több VLAN forgalmát

Ethernet és WLAN

  • Ethernet (IEEE 802.3): CSMA/CD – érzékeli az ütközést, exponenciális visszavárás
  • WLAN (IEEE 802.11): CSMA/CA – ütközés elkerülés (nem érzékelhető vezeték nélkül); RTS/CTS mechanizmus
  • Infrastruktúra mód: AP (access point) koordinál; ad-hoc: közvetlen kapcsolat

Template Method Viselkedési

Az algoritmus vázát az ősosztály definiálja, a részleteket az alosztályok valósítják meg. A "sablon metódus" hívja a primitív metódusokat.

Mikor: Van egy általános algoritmusod, de lépéseinek részletei változnak.

Strategy Viselkedési

Egy algoritmus-családot definiálunk, mindegyik külön osztályban. Futásidőben cserélhető. A Context tartalmaz egy Strategy referenciát.

Mikor: Különböző viselkedéseket szeretnél felváltva használni (pl. különböző rendező algoritmusok).

Különbség Template Method-tól: Strategy objektum szintű csere (kompozíció), Template Method öröklés szintű.

Singleton Létrehozási

Biztosítja, hogy egy osztályból csak egy példány létezzen, és globálisan elérhető legyen.

Megvalósítás: privát konstruktor, statikus getInstance() metódus.

SOLID-dal ellentétes lehet! Tesztelhetőséget rontja, globális állapot.

Observer Viselkedési

Egy-a-többhöz függőség: ha egy objektum (Subject/Observable) állapota változik, minden megfigyelője (Observer) automatikusan értesül.

Szereplők: Subject (tartja az Observer listát, notify()), Observer (update() metódus).

Példa: UI eseménykezelők, MVC mintában Model → View frissítés.

Composite Szerkezeti

Objektumokat fa struktúrában szervez, az egyedi és összetett elemeket azonos interfészen kezeli.

Szereplők: Component (interfész), Leaf (levél, nincs gyermeke), Composite (tartalmaz Componenteket).

Példa: fájlrendszer (fájl = Leaf, mappa = Composite), GUI fa.

Adapter Szerkezeti

Inkompatibilis interfészeket tesz együttműködővé. "Illesztő": a kliens elvárja az interfészt, az Adapter fordítja az Adaptee hívásait.

Példa: Régi API integrálása új rendszerbe, különböző formátumok konvertálása.

Adapter = Stratégia nélkül nem tudsz egy régi könyvtárat új kódba illeszteni.

Gyenge entitás

Nem rendelkezik saját kulcsattribútummal, más entitástól függ (kettős kerettel jelöljük). Részkulccsal + tulajdonos kulcsával azonosítható.

ER → Relációs leképezés ▼
  • Erős entitás: → saját tábla, kulcsattribútum lesz elsődleges kulcs
  • 1:N kapcsolat: → N oldalon idegen kulcs a kapcsolathoz
  • M:N kapcsolat: → külön kapcsolótábla, mindkét entitás kulcsával
  • 1:1 kapcsolat: → valamelyik oldalon idegen kulcs (kötelező részvétel oldala preferált)
  • Gyenge entitás: → tábla, kulcsa = részkulcs + tulajdonos PK (összetett PK)
  • Többértékű attribútum: → külön tábla az értékeknek

SELECT szerkezete

Végrehajtási sorrend (≠ írási sorrend):

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

WHERE vs HAVING

  • WHERE: egyedi sorokra szűr (GROUP BY előtt, aggregátum NEM használható)
  • HAVING: csoportokra szűr (GROUP BY után, aggregátum HASZNÁLHATÓ)
Ha aggregátum függvény van a szűrőben → HAVING. Különben → WHERE.

JOIN típusok

  • INNER JOIN: csak az egyező sorok
  • LEFT JOIN: bal tábla összes sora + egyező jobb oldaliak (hiányzó = NULL)
  • RIGHT JOIN: jobb tábla összes sora
  • FULL OUTER JOIN: mindkét tábla minden sora
